# 色彩勇者：三消镇魂曲 2.1.0 迭代与测试计划

## 1. 版本目标

2.1.0 是 2.0 纯三消 + 色谱卡牌架构的稳定性版本。目标不是增加新的棋盘玩法，而是让一次 Run 在中断、恢复、切换地图视图和领取战斗奖励时保持可解释、可复现的状态边界。

本版本的核心验收句：

> 玩家可以在战斗稳定阶段退出并恢复到同一战斗状态；地图可以记住视图；存档损坏时不能覆盖有效备份；奖励事务必须先于胜利演出落盘。

## 2. 本轮实现范围

| 模块 | 2.1.0 内容 | 验收重点 |
|---|---|---|
| 战斗续局 | 棋盘、敌人、战斗回合、步数、护甲、持续效果、色谱手牌、触发历史和上下文快照 | 恢复后不重复开场效果，不改变玩家 HP/护盾 |
| 稳定检查点 | 仅在非 resolving、非胜负终态产生检查点 | 结算中不写入半状态 |
| 棋盘校验 | 6x6、颜色合法、无预成消除、存在合法交换 | 非法快照拒绝，合法快照完整保留 |
| 存档可靠性 | `.tmp` 校验、原子替换、`.bak` 轮换、主档回退 | 主档损坏/缺失时恢复备份 |
| 色谱计数 | 完成计数保留任意合法字符串键，负数钳制为 0 | 紫、绿、白、混色、黑等扩展学派不丢失 |
| 地图视图 | 缩放、平移、章节视图和聚焦节点持久化 | 进度变化后聚焦可达节点，拖拽退出时状态清理 |
| 奖励事务 | 胜利后先创建并落盘奖励事务，再播放延迟演出 | 关闭窗口不应留下“已胜利但无奖励”的主状态 |
| 发布配置 | 工程版本、Windows 预设、截图工具和完整性测试统一为 2.1.0 | 可导出、文件名和版本资源一致 |

## 3. 测试分层

### 3.1 静态与冷启动

- 使用 Godot 4.6.3 Mono 执行 `--headless --editor --quit`。
- 检查 `SCRIPT ERROR`、引擎 `ERROR`、崩溃信号和非零退出码。
- 检查 2.1.0 版本号在 `project.godot`、`SaveManager.gd`、`export_presets.cfg`、菜单文案和发布测试中一致。

### 3.2 单元与系统回归

- `test_v2_1_recovery.gd`：战斗、地图视图、奖励提交和扩展色谱恢复。
- `test_save_manager.gd`：14 项原子写入、备份轮换、损坏回退和迁移测试。
- `test_map_canvas.gd`：7 项缩放、平移、边界和输入状态测试。
- `test_v2*.gd`：2.x 内容、地图模板、UI 合约、战斗边界和发布完整性。
- 全量 `tests/*.gd`：兼容旧版本迁移链，同时确认当前 2.0 战斗规则没有被历史测试误改。

### 3.3 运行时冒烟

在 1280x720 和 1600x900 下分别截取：主菜单、角色选择、誓约选择、档案地图选择、记忆档案、竖向路线地图和战斗 HUD。重点观察标题、节点、按钮、棋盘、敌人意图与色谱卡牌不重叠、不裁切。

人工冒烟流程：

1. 开始一局，选择角色与誓约，进入第一场战斗。
2. 完成至少一次有效交换和一次连锁，确认色谱完成即时结算。
3. 在稳定阶段退出进程，再次启动并恢复，确认棋盘、敌人 HP、护甲、手牌、回合和步数一致。
4. 在地图中滚轮缩放、按住拖拽、切换章节后退出，再进入地图确认视图保持。
5. 完成战斗，在胜利演出期间结束进程，重新进入确认奖励事务已落盘且不会重复领取。
6. 复制并破坏主存档，启动游戏确认自动回退 `.bak`；再删除主存档确认备份恢复。

## 4. 边界条件

- 存档缺少 `battle_snapshot`：按普通节点状态恢复，不创建空战斗。
- 战斗快照节点与当前节点不一致：丢弃战斗快照，不能阻塞地图恢复。
- 棋盘尺寸不是 6x6、颜色非法、有预成消除或无合法交换：拒绝恢复。
- `resolving=true`、`battle_over=true` 或敌人已死亡：不产生稳定检查点。
- 扩展色谱键为空、值为负数或不是数字：空键丢弃，数值按 0 处理。
- 主档损坏、主档缺失、临时文件残留、备份存在或备份也损坏：按优先级回退，不能覆盖有效 Profile。
- 地图窗口失焦、鼠标离窗、节点退出树或控件隐藏：清除拖拽捕获状态。
- 胜利演出尚未结束时进程退出：奖励事务仍必须存在；本版本不承诺跨进程 RNG 状态与未中断运行的未来随机序列完全一致。
