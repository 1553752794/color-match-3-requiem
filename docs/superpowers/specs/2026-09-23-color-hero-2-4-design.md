# 色彩勇者 2.4：色谱构筑与战术验证版

日期：2026-09-23

## 1. 版本目标

2.4 不以扩大内容数量为目标，而是验证当前核心战斗是否能产生清晰、可复玩的策略选择：

> 观察敌人意图，规划三次交换，完成目标色谱，利用谱序共鸣，并为敌人反击付出代价。

本版本优先改善战斗信息、构筑表达和奖励决策。保留 6×6 四色棋盘、三步回合、三张色谱、即时结算、跨回合共鸣、三章地图和现有存档协议。

## 2. 设计支柱

### 2.1 每次交换都应有目的

玩家应能在交换前理解：

- 本次交换会消除什么颜色和数量；
- 会产生多少色素；
- 哪些色谱会推进或触发；
- 是否会触发预期共鸣；
- 交换后敌人意图是否仍然可接受。

不要求预览未来完整棋盘，只预览当前交换可确定的结果。

### 2.2 构筑应能被玩家说出来

色谱、角色、遗物和奖励使用统一的构筑标签。第一批标签为：

- 燃烧
- 冻结
- 护盾
- 金币
- 灰蚀
- 连锁
- 共鸣
- 多色
- 自伤

标签用于筛选、奖励推荐和结算报告，不直接改变现有卡牌效果。

### 2.3 选择奖励，而不是堆积内容

战斗奖励继续兼容现有领取流程，但增加推荐信息：

- 稳定选择：低风险、适合当前角色；
- 风险选择：高收益或带副作用；
- 协同选择：与当前色谱、角色或遗物标签匹配。

2.4 第一阶段不实现完整自动推荐算法，先保证数据层能表达标签和推荐理由。

### 2.4 随机性应服务于计划

关键战斗效果不在本版本大规模改成确定性。2.4 先增加“可解释性”：

- 敌人意图和色谱条件在同一战斗信息层展示；
- 概率效果显示触发概率或条件；
- 随机结果使用明确的反馈文本；
- 不改变已有存档中的数值和历史行为。

## 3. 第一批实现范围

### 3.1 色谱标签数据

为现有色谱数据增加 `tags: Array[String]` 字段。

标签来自卡牌条件和效果，不创建新的卡牌类型。缺失标签时由数据校验器拒绝或给出明确错误，避免 UI 显示空标签。

新增数据访问接口：

- `GameData.spectrum_tags(card_id: String) -> Array[String]`
- `GameData.spectra_matching_tags(tags: Array[String]) -> Array[Dictionary]`

### 3.2 战斗目标色谱

允许玩家在战斗中将一张未触发色谱标记为“目标色谱”：

- 每回合最多一个目标；
- 目标色谱完成后自动清除目标状态；
- 目标状态进入战斗快照；
- 目标状态在重开战斗和读档后保持；
- 目标只影响提示和视觉，不改变色谱概率、条件或伤害。

建议的战斗管理接口：

- `BattleManager.set_target_spectrum(instance_id: String) -> bool`
- `BattleManager.target_spectrum_instance_id: String`

### 3.3 交换前结果预览

棋盘在检测到合法交换时发出预览数据，战斗层根据当前色谱和共鸣状态生成展示内容。

预览至少包含：

- 交换坐标；
- 消除颜色与数量；
- 预计色素；
- 预计级联最低值；
- 可触发的色谱实例 ID；
- 预计共鸣 ID；
- 敌人意图的简短风险提示。

预览不应修改棋盘、色谱进度、战斗统计或随机状态。

### 3.4 战斗奖励标签展示

战后色谱奖励卡显示：

- 卡牌已有名称、稀有度和效果；
- 1-3 个构筑标签；
- 与当前角色或已有牌组匹配时的简短原因；
- 不匹配时不显示虚假推荐。

### 3.5 流派统计

在结算统计中增加标签维度：

- 本局完成次数最多的标签；
- 标签相关色谱完成数；
- 标签相关色谱选择数；
- 主要颜色仍保留。

这些字段只用于报告和后续平衡分析，不影响结局判定。

## 4. 暂缓范围

本版本不实现：

- 八色棋盘；
- 新的基础颜色；
- 完整特殊棋子系统；
- 完整色谱移除商店；
- 角色双分支技能树；
- 新的永久货币；
- 城市、科技树、外交和多人；
- 新增大批量色谱；
- 改写 Save v4 或 Profile v1。

如果交换预览需要重构棋盘求解器，特殊棋子系统必须延后，不能为了视觉效果破坏现有 Board 快照和合法交换边界。

## 6. 验收标准

### 战斗

- 目标色谱可以选择、取消和自动清除；
- 目标色谱随战斗快照恢复；
- 合法交换预览不会改变实际战斗结果；
- 预览失败或数据异常时不阻塞正常交换；
- 普通消除仍不直接造成 HP 伤害；
- 色谱仍在当前操作链内即时结算；
- 共鸣生命周期和每回合最多一次规则不改变。

### 数据

- 所有正式色谱都有合法标签；
- 未知标签被校验器拒绝；
- 标签查询返回去重、稳定排序的结果；
- 历史旧数据缺失标签时有明确迁移默认值，不破坏旧存档。

### UI

- 目标色谱状态能在不遮挡棋盘的前提下识别；
- 交换预览不会替代实际反馈条；
- 奖励标签在 1280×720 和 1600×900 下不溢出；
- 战斗恢复、页面切换和重复点击不会产生旧节点反馈。

### 发布

- Godot 4.6.x 编辑器冷解析通过；
- 2.4 新增测试通过；
- 全量测试无 `SCRIPT ERROR` 或引擎 `ERROR`；
- Windows 导出和隔离存档启动通过。

## 7. 成功判断

2.4 的成功不是“增加了多少卡牌”，而是玩家在一局结束时能回答：

1. 我这一局主要围绕什么标签构筑？
2. 我为什么选择这些交换？
3. 哪次路线、奖励或色谱选择改变了我的打法？
4. 下一局我想主动尝试哪种不同构筑？
